# 작은 창과 확대 화면 가독성 검증

OPT-025는 최소 창에서 실행 막대가 본문을 덮고, 확대 시 가져오기 설명과 배치 표가 좁아지며, 완료 지표의 이름과 값이 붙어 보이던 문제를 개선한다. 본문은 별도로 스크롤하고 하단의 다음 작업은 자기 공간을 사용한다. 실행 버튼은 하단 한 곳에 유지하며 저장 위치와 세부 옵션은 본문에서 조정한다.

화면 배율은 Ctrl + + 또는 Ctrl + =로 확대, Ctrl + −로 축소, Ctrl + 0으로 초기화한다. 범위는 75–225%이며 새 실행은 기본 크기로 시작한다. 문서와 압축 설정을 바꾸지 않는다. 도움말도 현재의 세부 옵션 안 계획 위치를 안내한다.

## 실제 화면 관찰

기준은 `0190965`의 실제 Electron 화면이다. 외부 계정·문서 없이 같은 합성 문서 두 개와 잘못된 합성 ZIP 하나를 사용했다. 변경 전 9개와 변경 후 14개 화면을 현재 실행에서 캡처하고 직접 확인했다. 최소 720×520 콘텐츠 창의 100%·200% 화면을 비교했다. 확대 캡처는 Electron의 전체 웹 콘텐츠를 저장해 720×520 픽셀을 보존한다. 초기 CSS 영역만 잘린 캡처와 이전 프레임을 저장한 시도는 증거에서 제외했다.

| --- | --- | --- | --- |
| 1 | 가져오기 200% | 제목 생략, 설명이 한두 글자 폭으로 줄바꿈 | 양호: 제목·설명·선택 버튼을 순서대로 배치 |

일부 파일을 분석·저장하지 못했을 때도 그 파일을 통과 비율의 분모에 포함하고 실패·취소를 통과로 세지 않는다. 예를 들어 선택한 세 파일 중 두 개만 통과하면 `2/3`으로 표시한다. 설정의 새 압축 기준이 잘못됐더라도 이미 저장한 결과의 열기·확인은 유지한다. 새 압축 실행은 잘못된 입력을 계속 차단한다.

전체 화면과 단계별 메모는 로컬 `.tmp/ui-audit/readability-2026-10-16/report.html`에 있다. 이 보고서에는 변경 전·후 캡처 23개를 함께 배치한다. 캡처, ARIA 기록, 계산 결과와 합성 문서는 git 및 외부 업로드에서 제외한다.

## 동작과 접근성 검증 범위

`main/smoke/readabilitySmoke.ts`는 실제 Electron에서 기본 800×560/100%와 최소 720×520/75·100·125·150·175·200·225%를 사용한다. 가져오기, 긴 단일 파일 계획, 단일 완료, 일부 실패 배치 계획·완료의 5개 상태에서 40개 화면 조건을 검사한다. 본문·하단의 비겹침, 페이지와 본문의 가로 넘침, 다음 작업·가져오기·도움말·설정 버튼의 실제 hit test와 최소 클릭 영역, 중복 실행 버튼, 긴 이름을 확인한다. native 입력으로 확대·축소·초기화를 실행한다.

225%의 320 CSS 픽셀 화면에서 Chromium의 실제 접근성 트리에 표 하나와 파일별 행 이름 세 개가 유지되는지 검사한다. 손상된 입력·정상 원본의 SHA256을 확인하고 실제 worker·IPC·파일 저장으로 완료 상태를 만든다. 설정 입력 오류 뒤에도 결과 확인 버튼이 동작하는지 검사한다. 기존 문서 11개·설정 4개·HCI 9개에 가독성 3개 흐름이 추가됐다.

로컬 실제 화면의 계산 색상으로 일반 글자 4.5:1, 큰 글자 3:1을 기준으로 검사한다. [W3C 글자 대비 설명](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)에 따른 상대 휘도와 알파 배경 합성을 사용한다. 렌더링된 텍스트 샘플과 활성 컨트롤을 검사하며, 장식·비활성 컨트롤·화면 낭독용 숨김 텍스트는 제외한다. 체크박스는 연결된 레이블의 클릭 영역도 고려한다. 클릭 영역은 [W3C 최소 대상 크기 설명](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)의 24×24 CSS 픽셀을 기준으로 확인한다. 화면 폭 검사는 [W3C 리플로 설명](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)을 참고했다.

14개 화면에서 렌더링된 텍스트 샘플 936개를 계산했으며 관측 최소 대비는 4.564:1이었다. 검사한 기준 미달 텍스트와 활성 클릭 영역 미달은 각각 0개, page error도 0개였다. 화면 간 반복 샘플을 포함한 수치다. 같은 새 프로필로 기본 배율 100% → native 단축키 225% → 프로세스 재실행 100%도 확인했다. 원본 합성 입력의 해시는 유지됐다.

이 검증은 해당 화면·배율·계산 색상과 Chromium 접근성 트리의 범위다. 모든 WCAG 항목, 실제 스크린리더 발화, 운영체제의 모든 글꼴·배율·고대비 조합 또는 한컴 문서 표시를 승인하지 않는다. 한컴·대표 실문서·기관 PC 검증은 OPT-021에 남아 있다.

## 배포 검증 보완

최초 구현 `7412856`은 Windows 소스의 27개 흐름을 통과했으나, 체크아웃 밖 실제 패키지의 초기 글꼴 검사에서 180초 시간 초과가 발생했다. 글꼴 증거 출력 전에 멈췄으므로 패키지 통과로 취급하지 않는다. 같은 시점의 Linux 검사는 종료되지 않아 취소했다. 숨겨진 창에서 animation frame을 기다리는 검사를 실제 창 표시 후 수행하도록 보완하고, 글꼴 대기는 15초 후 명시적으로 실패하게 했다. 제품의 백그라운드 제한은 변경하지 않는다. [Electron 창·표시 및 백그라운드 동작 문서](https://www.electronjs.org/docs/latest/api/browser-window)를 참고했다. 최종 통과 기록은 보완 커밋의 결과로 별도 남긴다.
