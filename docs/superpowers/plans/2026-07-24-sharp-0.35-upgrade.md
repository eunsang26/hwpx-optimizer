# sharp 0.35 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade workspace + Electron Windows prep + CLI portable packaging from `sharp@0.33.5` to a single pinned **sharp 0.35.x** so the libvips/sharp high advisory is cleared without changing optimizer policy.

**Architecture:** Introduce one shared pin module (`scripts/sharpPin.mjs`) consumed by CLI portable constants and Electron `prepare-win-sharp-runtime.mjs`. Bump root `package.json` / lockfile, revalidate win32 native filenames, keep PE and stage verifiers green, then tighten CLI portable audit level if residual advisories allow.

**Tech Stack:** npm, sharp 0.35.x, `@img/sharp-win32-x64`, Node 20.20.2, Vitest, existing CLI portable / Electron packaging scripts.

**Spec:** [docs/superpowers/specs/2026-07-24-sharp-0.35-upgrade-design.md](../specs/2026-07-24-sharp-0.35-upgrade-design.md)

## Global Constraints

- Pin **exact** sharp 0.35.x (prefer newest available at implement time; start candidate **0.35.3**).
- Node runtime floor stays **≥20.20.0** / pin **20.20.2**.
- No optimizer mode/policy/threshold changes unless a test proves a false failure caused by metric drift (document evidence before loosening).
- Never overwrite original HWPX inputs.
- Keep win32-only natives in CLI portable ZIP; no linux sharp in stage.
- Sample HWPX files stay uncommitted.
- Conventional Commits; one intent per commit.
- Prefer Node 20: `export NVM_DIR="$HOME/.nvm"; . "$NVM_DIR/nvm.sh"; nvm use 20`.
