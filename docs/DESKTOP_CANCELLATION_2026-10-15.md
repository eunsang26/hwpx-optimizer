# 데스크톱 취소·시간 초과·정상 종료 검증

검증일: 2026-10-15. OPT-012와 PR #9의 근거다. 실제 사용자 문서 대신 자체 생성한 HWPX만 사용했다. 화면, 문서, 최적화 결과는 로컬 `.tmp`에만 보관하고 원격 저장소나 Actions 산출물로 업로드하지 않는다.

## 저장 소유권과 완료 시점

기존에는 계산과 저장이 같은 worker에 있어 `terminate()`가 overwrite backup과 결과 공개 사이를 끊을 수 있었다. 이제 worker는 읽기·분석·이미지 처리·검증을 수행하고 바이트와 보고서만 main에 전달한다. main의 비동기 파일 서비스가 경로 권한 검사, 예약, 저장, rollback과 정리를 수행한다. 큰 전용 ArrayBuffer는 소유권을 전달하며, 같은 buffer를 참조하는 입력 캐시를 제거해 이후 분석의 detached buffer 사용을 막는다.

작업 잠금은 권한 검사부터 복구 완료까지 유지한다. 저장 전 취소나 시간 초과는 AbortSignal로 전달하고, 진행 중인 파일 연산이 끝난 뒤 기존 문서/보고서를 복원한다. 취소 응답도 이 복구를 기다린다. 두 결과 공개 후 동기적으로 commit을 결정하며 이후 취소는 이미 완료된 결과를 유지한다. 복원에 실패하면 사용자 대체 파일을 보존하고 복구 디렉터리를 오류로 표시한다. 정상 앱 종료는 새 요청을 막고 복구 또는 완료 후 정리가 끝날 때까지 기다린다.

worker 종료 시 해당 세대의 요청만 실패시킨다. 중단 중인 worker의 늦은 응답은 무시하며 다음 요청은 새 worker를 사용한다. 사용자 취소, 진행 응답 시간 초과, 예기치 않은 worker 종료 및 복구 실패를 각각 구분한다. batch의 남은 항목 중단이 현재 파일의 실제 성공/실패를 덮어쓰지 않도록 결과 판정도 분리했다.

## 실제 Electron 화면과 흐름

격리한 설정과 합성 입력으로 Electron을 실행하고 승인된 로컬 Playwright를 사용했다. 테스트는 실제 계산과 파일 연산을 수행하며, 정확한 취소 시점을 만들기 위해 로컬 실행 중 연산 경계에서만 일시 정지했다. 최적화 응답이나 저장 결과를 가짜 성공으로 대체하지 않았다.

1. 계산 완료 후 공개 전에 취소: 출력 파일이 없고 원본과 폴더 내용이 유지된다. 화면은 취소를 알리고 재시도가 가능하다.
2. 실제 commit 후 정리 중 취소: 완료 결과와 유효한 보고서가 남고 화면은 결과를 표시한다.
3. 결과의 `처음으로`: 파일 선택 화면으로 돌아가며 저장된 결과는 유지한다.
4. overwrite backup 이동 후 정상 앱 종료: 이전 결과와 보고서를 복원하고 임시 stage·예약·backup을 남기지 않는다.

## 복구 보장의 한계

worker 강제 종료는 main 저장을 끊지 않는다. 사용자 취소·처리 시간 초과·정상 앱 종료의 복구는 위 테스트 범위에서 보장한다. OS가 진행 중인 파일 연산을 무기한 반환하지 않으면 해당 연산과 복구를 기다린다.

**main 프로세스 강제 종료, OS 종료 또는 전원 장애의 자동 재시작 복구는 구현하지 않았다.** 여러 파일을 한 번에 crash-atomic하게 공개하는 durable journal도 없다. 이런 경우 `.hwpx-save-*`의 이전 파일을 수동 복구해야 할 수 있다. CLI 프로세스를 강제로 종료하는 경우도 같은 제한이 있다. 중간 이름을 다른 프로세스가 관찰할 수 있고 hardlink 미지원 파일시스템의 배타적 복사는 부분 바이트가 보일 수 있다.
